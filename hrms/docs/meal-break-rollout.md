# 吃飯休息打卡與推播上線

## 行為

- 原始上下班欄位保留，新增 `punch_action` 記錄上班、午休開始／結束、上午／下午吃飯、提前結束吃飯與下班。
- 午休只在發布的 `WEEKDAY_SPLIT` 班表提供；吃飯休息上午、下午各一次。
- 下午預定 16:30 開始，員工實際打卡後才開始 30 分鐘倒數。
- 滿 30 分鐘依開始紀錄推算結束，不建立假造的員工返回打卡；有後續打卡時提前截斷休息。
- 吃飯提醒在開始後 27 分鐘排入佇列，cron 每分鐘處理，裝置收到時間可能受網路、作業系統與排程延遲影響。
- 缺卡不阻擋後續事件；缺少的事件可以申請補卡，由管理員核准後納入計算。
- 未記錄、未核准的吃飯不自動扣工時。提前結束依實際時間扣除；中斷不足 30 分鐘不代表已滿足完整休息。
- 實際工時保留班表外時間；排班內計薪分鐘獨立保存，避免與核准加班重複計薪。

## 上線順序

1. 先備份並套用 `202609260002`、`202609260003`、`202609260004` 三個 migration，再部署前端。
2. 設定伺服器環境變數：`VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY`、`VAPID_SUBJECT`、`CRON_SECRET`。私鑰與 cron secret 不可加入 Git。
3. 首次用 `web-push.generateVAPIDKeys()` 產生固定金鑰；此工作區已於忽略的 `.env.local` 準備一組。日後保留同一組金鑰，避免既有訂閱失效。
4. `vercel.json` 設定每分鐘執行 `/api/cron/meal-reminders`。Vercel 每分鐘 cron 需要 Pro 或 Enterprise；Hobby 不能直接部署此 cron 設定。若目前是 Hobby，需改用能每分鐘呼叫該端點的外部排程，攜帶 `Authorization: Bearer <CRON_SECRET>`，再移除 Vercel cron 設定。不可未經同意升級付費方案。
5. iPhone 員工須加入主畫面，再從首頁「開啟吃飯推播提醒」允許通知。Android／桌面依瀏覽器支援開啟通知。
6. 正式驗收需在實機執行一次吃飯休息，切到背景或鎖屏，確認提醒；程式與模擬測試無法保證各手機通知實際送達。

## 權限與失敗處理

- 仍採原本 GPS 圍欄／QR 授權驗證；QR 全球單次使用與 30 秒冷卻保留。
- 一般登入者不能讀取其他員工的推播端點或取出提醒佇列；送出提醒與佇列處理僅 service role 可執行。
- 端點限制為支援的瀏覽器推播服務，避免任意網路請求；每帳號最多 10 個訂閱。
- 提前結束、下班、作廢吃飯紀錄會取消未送出的吃飯提醒。
- 同一分鐘的重複 cron 由資料庫租約避免重複領取；重試會跳過已成功送出的訂閱。過期提醒不補送。
- service worker 僅處理推播，不快取已登入 HR 資料。

## 驗證

`npm run lint`、`npm run typecheck`、`npm test`、`npm run build`。

資料庫整合測試涵蓋：明確事件的 GPS／QR 打卡、QR 單次使用、漏上班卡的下午班段配對、吃飯扣除、提前中斷、作廢、補卡待審與提醒租約。
